# FEAT-001 implementation audit — 2026-09-05

## Scope

This round implements local search-first navigation on the Android launcher home screen. It adds the search/ranking engine, local recent-history persistence, result UI, lifecycle and accessibility plumbing, complete string coverage for all existing locales, and automated tests. It also fixes only the CORE-001 seam required to prevent stale search results after app-state changes; CORE-001 and A11Y-001 remain separate backlog stories.

Base commit: `a8701ba1d34e34b04d26a24f7108188359d4669e`. The reviewed candidate is the uncommitted working-tree diff above that base.

Device policy for this audit: only the owner-designated TECNO KJ7, serial `115333744A005844`, is valid device evidence. Pixel was explicitly excluded and was not used by the final qualification run.

## Findings and fixes

- Initial search-bar transparency allowed lens icons to visually collide with the search icon. The audited version uses a high-opacity light/dark surface.
- The widget test no longer relies on platform-private input injection. It mutates the widget on the Activity main thread and asserts rendered state through supported test APIs.
- The existing launcher integration test assumed that `LensView` must still be invisible immediately after launch. Installed-app loading can legitimately complete before the assertion, so the test now verifies stable layout presence and the search entry point instead of timing-dependent visibility.
- `ActHome` previously retained stale state when all apps disappeared and treated label, component, lock and open-count changes as identical. The audited implementation clears or refreshes lens/search state for those changes.
- Re-audit found that `ActHome` did not observe `appsUpdated` or `appsEdited`, so package/update events could leave an active search stale. Both LiveData streams are now observed and covered by event-driven integration tests.
- A non-empty source list containing only hidden apps previously left an empty `LensView` visible. The filtered-empty state now hides the lens and refreshes the active search.
- The adapter advertised stable IDs derived from a 32-bit string hash, which could collide. Stable IDs were removed because this bounded adapter replaces its list atomically and does not need them.
- Normalization now collapses internal whitespace, duplicate recent keys retain their first MRU position, and physical Enter joins SEARCH/GO/DONE as a launch action.
- A physical-device instrumentation benchmark was added so the 400-app latency gate runs on the designated Tecno hardware, not only on the host JVM.
