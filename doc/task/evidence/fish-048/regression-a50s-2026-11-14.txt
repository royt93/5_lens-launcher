FISH-047/048 regression on a Samsung A50s R58MA6WYRPE (2026-11-14), owner policy "hãy chuyển sang dùng a50 cho mọi phiên". Single user 0, window/transition/animator
scale 0.0 (so LensPhysicsPolicy.shouldReduceLensMotion is true), font 1.3, 60 Hz-class low-end device. Backup of both APKs and the app data before, exact restore after
(data 14/14 files, both APK SHA256, 461 packages, system settings and /data/local/tmp all identical).

Reachability on the A50s (3 runs each): LensViewNeighbourLabelsReachabilityTest OK 5/5 x3, LensViewRecentDotsReachabilityTest OK 10/10 x3.

Whole packages, same device, same conditions, compared BY TEST NAME against a baseline build of c2857803 (the commit before FISH-047), built in a temporary git worktree:
  views: new build 21/318 fail, baseline 21/303 fail, the same 21 tests (nothing new, nothing fixed).
  ui:    new build 8/562 fail, baseline 7/560 fail, 6 tests in common.
         only in the new build: NeighbourLabelsFrameBudgetSmokeTest and RecentDotsFrameBudgetSmokeTest (see below).
         only in the baseline: ResetDefaultsWidgetTest.cancelLeavesEveryValueUntouched (the known first-launch/focus flake; ResetDefaults passed in the new-build run).

The 21 views failures are environmental on this device, not caused by FISH-047/048: with animator scale 0.0 the lens runs in reduced-motion, so tests that expect inertia lag,
focus snap, hover magnify, elastic overscroll, sharp-cluster haptics and pinch state cannot reach their effect. The failing classes (all identical in the baseline):
AllOpticalEffectsCombined, ElasticOverscrollWidget, FocusRingIntegration, FocusSnapClusterInteraction, FocusSnapProfile, FocusSnapReachability, HoverMagnifyReachability,
HoverMagnifySelfRedraw, InertiaIntegration, PinchIntegration, SharpClusterHapticReachability, SharpClusterHapticWidget. This also means the A50s cannot exercise those features at all.
FISH-047/048 labels and dots are NOT motion effects, which is why their reachability tests pass here while the motion ones do not.

The two new smoke failures are a test-calibration issue, not a regression: they assert at least 100 frames in 6 s per run (MIN_FRAMES), calibrated on 120 Hz phones.
On the A50s the first run after a cold start produced 82-102 frames (about 14-17 fps) and the later runs 165-177. The assertion that failed is the "enough frames" guard,
the dots/labels positive controls themselves passed (labelsSeen=[3,3,3,3]).

Frame numbers on the A50s (NeighbourLabelsFrameBudgetSmokeTest, 4 pairs, order alternated):
  OFF frames=583 mean=23.64ms p90=28.96ms p99=35.99ms; ON frames=616 mean=20.62ms p90=28.16ms p99=36.68ms; per-run p99 within ~2 ms except the cold first run.
Reading: per-frame cost not higher with the switch on; the first run after a cold start is the slowest with either setting. These numbers are not comparable with the Pixel or KJ7.

--- Follow-up, same day: the frame guard recalibrated for a 60 Hz phone (owner picked "lower the guard and drop the cold run") ---
Both smoke tests (NeighbourLabelsFrameBudgetSmokeTest, RecentDotsFrameBudgetSmokeTest) now run one discarded warm-up measurement first and require MIN_FRAMES = 60 (was 100)
per run; both pass on the A50s. The positive controls are unchanged (3 dots / 2 labels drawn when on, 0 when off).
Numbers after the change (4 kept pairs each, order alternated):
  labels test: OFF mean 21.45 / p99 33.34 ms, ON mean 20.13 / p99 33.47 ms.
  dots test:   OFF mean 20.61 / p99 33.42 ms, ON mean 21.75 / p99 50.25 ms (max 150 ms).
The ON p99 of the dots test is dominated by ONE frame of 150 ms in on-1, the first kept ON run (p99 107.90 ms, max 150.00). Setting the first kept run of each side aside, the other three:
  dots test:   OFF runs 2-4 mean-of-means 20.62 ms, p99 32.29 ms; ON runs 2-4 mean-of-means 20.71 ms, p99 31.03 ms.
So per-frame cost does not look higher with the switch on; the 150 ms frame is a one-off in the warm-up-adjacent run. This is a single sample on one low-end device, and it is not evidence
that no such hitch ever happens with the dots on: on-1 is the only run with it and it is not reproduced.
