# FEAT-002 / CORE-001 / DB-001 implementation re-audit — 2026-09-06

## Scope

This round completes the application-owned installed-app refresh pipeline, moves Room access off the UI thread with atomic updates and explicit migrations, and delivers local smart organization: favorites, folders, pinned start/end zones, drag reorder, and equivalent menu actions.

Base commit: `b26724c`. The reviewed candidate is the uncommitted working-tree diff above that base.

Device policy: every ADB command in this round used the explicit TECNO KJ7 serial `115333744A005844`. Pixel and emulator targets were excluded.

## Findings and fixes

- Refresh requests previously launched unrelated application jobs. One application-owned pipeline now debounces bursts, cancels the previous request and guards commits with a monotonically increasing generation.
- Loader failures now publish an error while preserving the last good immutable snapshot.
- Room main-thread queries and destructive downgrade recovery were removed. DAO APIs are suspend functions and public UI mutations update memory optimistically before application-scope IO persistence.
- Database versions 9 and 10 add unique component identity plus favorite/folder/pinned fields with exported schemas and explicit migrations from the Sugar-era schema.
- Open-count increments and multi-row reorders are transactional. Reorder writes use a revision plus mutex so an older queued order cannot overwrite the latest gesture.
- Organization is owner-controlled only. Stable component rows are retained while packages are absent, enabling recovery when the same component is reinstalled.
- Initial lint found 15 missing-translation errors for the new labels. English and Vietnamese are maintained in this wave; other locales explicitly fall back to English.
- Re-audit found that reorder persistence did not notify launcher observers; every committed drag/menu reorder now emits `AppsEditedReceiver`.
- Re-audit found that PackageManager and Room loader failures could be converted into an empty successful snapshot. They now propagate to the refresh error state and preserve the last good list; the error toast is dispatched on main.
- Re-audit found that rapid edit events could race in independent sort jobs. Sorting is now one application-owned cancel-latest pipeline with a generation guard and dedicated newest-wins/failure/cancel tests.
- Re-audit found that rapid writes for one component could complete out of order. Favorite/folder/pin, visibility, lock and palette writes now use per-component/per-field revision guards and mutexes; a physical integration test verifies the newest organization state in Room.
- Folder truncation now counts Unicode code points and cannot split an emoji surrogate pair.
